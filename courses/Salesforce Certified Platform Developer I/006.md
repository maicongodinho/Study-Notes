# Objects, Tabs, Users, and Profiles in Salesforce

## Summary

Salesforce stores business data in objects, presents data through tabs and apps, and controls user access through profiles and permission sets.

---

## Key Concepts

### Objects, Fields, and Records

- An **object** is a database table.
- A **field** is a column on an object.
- A **record** is a row of data in an object.

### Tabs and Apps

- A **tab** provides quick access to an object.
- An **app** is a collection of tabs and related features.
- Salesforce provides standard apps such as Sales, Service, and Marketing.

### Users, Profiles, and Permission Sets

- Every user must have exactly one **profile**.
- A profile defines baseline permissions, including access to apps, tabs, and objects.
- Profiles define CRUD permissions: Create, Read, Update, and Delete.
- **Permission sets** grant additional permissions beyond the profile.
- A user can have multiple permission sets.
- Salesforce includes standard profiles; custom profiles can be created or cloned.

### Setup Locations

- Manage users in **Setup → Users → Users**.
- Manage profiles in **Setup → Users → Profiles**.
- Changing a profile changes the apps and features visible to its users.

---

## Certification Tips

- An object is a table, a field is a column, and a record is a row.
- Every user has exactly one profile.
- Permission sets extend a profile; they do not replace it.
- CRUD does not include Execute.

## Key Takeaways

- Objects store data as records and fields.
- Tabs expose objects, and apps group tabs and related features.
- Profiles provide baseline access, while permission sets add access.
- Every user has one profile and may have multiple permission sets.
