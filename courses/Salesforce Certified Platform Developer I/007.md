# Standard and Custom Objects in Salesforce

## Summary

Salesforce provides standard objects for common business data, while custom objects store organization-specific information. Object Manager is used to create and configure both objects and their fields.

---

## Key Concepts

### Standard and Custom Objects

- Standard objects include Account, Contact, and Lead.
- Custom objects store business-specific data not covered by standard objects.
- Every object includes standard fields such as Name, Id, and Created Date.
- Custom fields can be added to standard and custom objects.

### Object Configuration

- Manage objects in **Setup → Object Manager**.
- Each object has a label and an API name.
- Use the API name when referencing an object in Apex.
- Manage fields in **Object Manager → Object → Fields & Relationships**.
- The record name can use Text or Auto Number.
- Auto Number supports display formats, such as `EN-{000}`.

### Tabs and Features

- Reports, activities, field history, and Chatter can be enabled for an object.
- A tab can be created while creating a custom object.
- Profile settings control tab visibility.
- Tabs can be added to multiple apps.

### API Name Convention

- Custom object API names end with `__c`.
- Standard object API names do not use `__c`.

---

## Certification Tips

- Choose a custom object when standard objects do not meet the business need.
- Apex references API names, not labels.
- The `__c` suffix identifies custom objects and custom fields.
- Object Manager is the central place for object and field configuration.

## Key Takeaways

- Standard objects support common Salesforce use cases; custom objects support unique business needs.
- Object Manager configures objects and fields.
- API names are used in Apex, and custom object API names end in `__c`.
- Record names can be text or auto-generated numbers.
